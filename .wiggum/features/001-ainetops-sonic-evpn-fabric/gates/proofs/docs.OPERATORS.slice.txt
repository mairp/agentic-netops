    16	## Compatibility matrix and pins
    17	
    18	All platform versions are pinned in versions.lock.yaml and verified by make verify-compat.
    19	- Kubernetes, controller-runtime, Go toolchain
    20	- Kubenet/KUID release and commit (single API shape)
    21	- SDC (core/config-server/schema-server releases)
    22	- Containerlab version
    23	- SONiC images (sonic_vs, optional sonic_vm) and their YANG compatibility
    24	- Tooling images (gNMIc, OTel Collector, Prometheus, Grafana, Flow plugin) pinned by digest
    25	
    26	See: versions.lock.yaml
    27	Run: make verify-compat
    28	
    29	## Resource sizing
    30	
    31	Reference lab (8 SONiC nodes + 4 Linux endpoints):
    32	- Host CPU: 8 vCPU minimum (16 recommended)
    33	- Host Memory: 16 GiB minimum (32 GiB recommended)
    34	- Disk: 40 GiB free (logs, images, PVCs)
    35	- Kind cluster: 1 control-plane node
    36	- Prometheus PVC: 5 GiB (configurable)
    37	
    38	Preflight enforces minimal CPU/RAM/disk and tool versions.
    39	
    40	## Image acquisition
    41	
    42	- SONiC VS: import the pinned container image (versions.lock.yaml.sonic_images.sonic_vs.image)
    43	- SONiC VM (optional conformance profile): build via vrnetlab and record digest in versions.lock.yaml; requires KVM (/dev/kvm) and nested virtualization
    44	- All other platform images are pulled by Kubernetes from pinned digests
    45	
    46	## EVPN/SRv6 mapping limitations
    47	
    48	- VPWS/E-Line is represented by a dedicated 2-attachment L2VNI; full pseudowire/RFC 8214 feature parity is NOT claimed
    49	- RSVP-TE, SR-MPLS policies, pseudowire OAM/control-word, multicast VPN, and complex QoS/OAM are unsupported
    50	- Only qualified YANG paths are rendered; unsupported fields reject the translation before any device change
    51	
    52	## Telemetry pipeline and topology presentation
    53	
    54	- gNMIc runs in-cluster and subscribes to SONiC targets; it exports OTLP to the OTel Collector
    55	- OTel Collector normalizes and exports to Prometheus (in-cluster metrics store)
    56	- Grafana consumes Prometheus and the generated topology ConfigMap (monitoring/ainetops-topology) to render orchestration, pipeline health, and topology views
    57	
    58	See manifests under deploy/observability/ and deploy/gnmi/
    59	
    60	## Operator quickstart and lifecycle commands
    61	
    62	- Provision: ./scripts/provision.sh --profile sonic-vs --cluster-name ainetops
    63	- Teardown: ./scripts/off.sh --cluster-name ainetops [--delete-kind true] [--capture-evidence true]
    64	- Capability gate: make lab-qualify (blocks downstream on failure)
    65	
    66	## Recovery procedures
    67	
    68	- Idempotence: re-run scripts/provision.sh to converge to Ready; unchanged intent results in no SDC spec write (verified by tests)
    69	- Partial failures: controllers surface Degraded and exact target errors; recover by fixing cause and re-running provision
    70	- Teardown: scripts/off.sh is safe from any partial state; it removes the containerlab lab, optionally deletes the Kind cluster, removes the owned Docker network, and cleans up lab-generated secrets
    71	
    72	## Break-glass finalizer procedure
    73	
    74	Controllers add ainetops.dev/finalizer to owned resources to delete downstream SDC intent first. If a controller or the API becomes permanently broken, an operator may break-glass:
    75	
    76	1) Inspect finalizers:
    77	   kubectl get networkdevices.network.kubenet.dev -A -o jsonpath='{range .items[*]}{.metadata.namespace}/{.metadata.name} {.metadata.finalizers}\n{end}'
    78	
    79	2) Remove the finalizer explicitly acknowledging loss of managed cleanup:
    80	   kubectl -n <ns> patch networkdevice <name> --type=json -p='[{"op":"remove","path":"/metadata/finalizers"}]'
    81	
    82	This skips ordered deletion of SDC intent and should be followed by a manual cleanup of any residual SDC Config resources.
