     1	# AINETOPS SONiC EVPN/VXLAN — Operator and Developer Guide (T075)
     2	
     3	This guide covers operator/developer documentation for Phase 8 acceptance: compatibility matrix, resource sizing, image acquisition, EVPN/SRv6 mapping limitations, telemetry pipeline, topology presentation, recovery, and the break-glass finalizer procedure.
     4	
     5	## Compatibility matrix
     6	
     7	- Source of truth: versions.lock.yaml (immutable pins):
     8	  - Kind binary/node image, Kubernetes version
     9	  - Kubenet/KUID release/commit and API shape
    10	  - SDC releases/commits (core, config-server, schema-server)
    11	  - Containerlab version
    12	  - Tooling images (gNMIc, OTel Collector, Prometheus, Grafana, Grafana Flow plugin)
    13	  - SONiC image digests for profiles and their YANG compatibility mapping
    14	- See: versions.lock.yaml
    15	- Contract: scripts/lib/verify_pins.sh enforces immutability and cross-field consistency. The provider validates SONiC image/schema/mapping compatibility on reconcile and blocks when mismatched (SchemaMismatch) per contracts.
    16	
    17	## Resource sizing
    18	
    19	Minimum host resources (preflight enforced):
    20	- CPU cores: 4 (AINETOPS_MIN_CPU)
    21	- Memory: 8 GiB (AINETOPS_MIN_MEM_MB=8192)
    22	- Disk free: 20 GiB (AINETOPS_MIN_DISK_MB=20480)
    23	
    24	Runtime footprint (reference scale: 2 spines, 2 leaves, 4 endpoints, 1 Kind control-plane node):
    25	- Kind cluster: 1 node (control-plane) using the pinned node image; ~2–3 GiB RAM under load
    26	- Containerlab: 4 SONiC nodes (sonic-vs) + 4 Linux endpoints; requires a Docker-compatible runtime and a host MTU ≥ 1500
    27	- Observability: OTel Collector (~100–200Mi), Prometheus (~256–512Mi with PVC), Grafana (~256–512Mi)
    28	
    29	Adjustments:
    30	- The sonic-vm conformance profile requires KVM/nested virtualization and significantly more CPU/RAM. Preflight enforces /dev/kvm when --profile=sonic-vm.
    31	
    32	## Image acquisition
    33	
    34	- SONiC images are not redistributed in this repository. Operators must acquire and locally import the image whose digest matches versions.lock.yaml.
    35	- The fast profile uses containerlab-supported sonic-vs (pinned digest). The conformance profile uses a locally built sonic-vm image (pinned digest) created with vrnetlab.
    36	- All controller/observability images are pinned by immutable digest in deploy/**.yaml.
    37	
    38	## EVPN/SRv6 mapping limitations
    39	
    40	- Supported EVPN mappings per spec:
    41	  - VPLS/multipoint L2VPN → EVPN bridge domain with unique L2VNI, attachment VLANs, import/export RTs
    42	  - L3VPN → Tenant VRF with L3VNI, RD/RTs, Type-5 routes where supported
    43	  - VPWS/E-Line → Dedicated two-attachment bridge domain and L2VNI (limited equivalence; not full pseudowire parity)
    44	  - Symmetric IRB for integrated L2/L3
    45	- Unsupported or limited features are rejected with structured findings before any device mutation: RSVP-TE, SR-MPLS policy, pseudowire OAM/control-word, multicast VPN, complex QoS/OAM, service chaining, and unknown properties.
    46	- Translation is all-or-nothing; no partial intent is applied on failure.
    47	
    48	## Telemetry pipeline
    49	
    50	- gNMIc runs inside the Kind cluster as the sole SONiC device-metric collector. It subscribes to interface, BGP, and SRv6 MySID counters and exports OTLP to the OTel Collector.
    51	- OTel Collector processes and exposes Prometheus scrape endpoints.
    52	- Prometheus scrapes OTel and other instrumented targets and retains metrics on a PVC.
    53	- Grafana uses a provisioned Prometheus datasource and dashboards as code. The Grafana Flow plugin is pinned by digest; anonymous access is disabled; admin credentials are generated at runtime via a Kubernetes Job.
    54	- SDC subscribe is disabled to avoid duplicate device series; only gNMIc provides SONiC metrics.
    55	
    56	## Topology presentation
    57	
    58	- A versioned topology ConfigMap (deploy/observability/topology-configmap.yaml) is generated from containerlab inspect output and labeled by the orchestration. Grafana’s Flow panel renders a physical fabric view using this ConfigMap and Prometheus metrics.
    59	- Dashboards provided: physical-fabric.json, sdc-orchestration.json, srv6-service-path.json, pipeline-health.json (embedded in deploy/observability/grafana.yaml ConfigMaps).
    60	
    61	## Recovery procedures
    62	
    63	- Lab qualification failure (sonic-vs):
    64	  - Run make off or scripts/off.sh to cleanly teardown.
    65	  - Re-provision with the sonic-vm conformance profile: scripts/provision.sh --profile sonic-vm.
    66	- Controller or SDC degraded:
    67	  - Inspect Conditions and Events on SRv6Service, NetworkDevice, and SDC Config/Target.
    68	  - The provider blocks downstream writes on schema/compatibility and validation failures and leaves last-known valid desired state intact.
    69	- Metrics pipeline outage:
    70	  - Controllers remain functional; observability alerts indicate OTel/Prometheus/gNMIc issues. See deploy/observability/rules/ainetops.rules.yaml alerts for guidance.
    71	
    72	## Break-glass finalizer procedure
    73	
    74	If a SRv6Service or provider-owned resource is stuck due to external issues and normal deletion does not proceed, remove finalizers explicitly as a last resort and allow the cluster to clean up owned resources:
    75	
    76	- SRv6Service finalizer removal (example name: example-srv6):
    77	
    78	```bash
    79	kubectl -n default patch srv6service example-srv6 --type=json \
    80	  -p='[{"op":"remove","path":"/metadata/finalizers"}]'
    81	```
    82	
    83	- Provider Config finalizer removal (if applicable to provider-created SDC resources):
    84	
    85	```bash
    86	kubectl -n sdc-system patch config <name> --type=json \
    87	  -p='[{"op":"remove","path":"/metadata/finalizers"}]'
    88	```
    89	
    90	- After break-glass, use scripts/off.sh to complete teardown and ensure no unmanaged resources remain.
    91	
    92	## Developer notes
    93	
    94	- Do not log secret values. Use structured Conditions and reason strings.
    95	- All images and plugins must be pinned by digest; deny-list CI enforces boundary terms. Run make supply-chain and make denylist locally.
    96	- The only lifecycle implementations are scripts/provision.sh and scripts/off.sh; Make targets are wrappers only.
