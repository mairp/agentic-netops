     1	# sonic-vs-gnmi — the SRv6/gNMI-qualified lab image
     2	
     3	`localhost:5000/sonic-vs-gnmi:202605@sha256:c04b9edd49bb0037ac9d01fde8715d4c37eb45d7a68710ba9d64ac27b1870768`
     4	
     5	## Why this image exists
     6	
     7	The lab was pinned to `netreplica/docker-sonic-vs:20220111` (kept as
     8	`sonic_vs_base` in `versions.lock.yaml`). That build ships **no gNMI server at
     9	all**, so `scripts/lib/qualify.sh` had nothing to talk to and the capability gate
    10	failed closed — correct behaviour, but it made SRv6 conformance (SC-013)
    11	unprovable in this environment. The gap is a property of a build frozen since
    12	January 2022, not a misconfiguration.
    13	
    14	The upstream community `docker-sonic-vs.gz` artifacts (sonic.software, branches
    15	202405/202411/202505/202511) do **not** close it either: they carry
    16	`sonic-srv6.yang` but no telemetry binary, because upstream ships gNMI as a
    17	separate `docker-sonic-telemetry` container. Verified 2026-08-31 against the
    18	202505 build (build 1207609): `/usr/sbin/telemetry` absent, zero
    19	`program:telemetry` entries.
    20	
    21	So this image layers a `sonic-gnmi` telemetry server onto the pinned base.
    22	
    23	## Provenance
    24	
    25	| Component | Source |
    26	|---|---|
    27	| base image | `localhost:5000/sonic-vs:202605@sha256:097d1551…` (`sonic_vs_base`) |

    29	| build libs | the base image's own `libswsscommon`/`libnl-3`/`libnftnl`/`libyang` — the binary is linked against the runtime it will execute in |
    30	
    31	## What it adds
    32	
    33	- `/usr/sbin/telemetry` + `/usr/sbin/schema` (CVL YANG schema dir)
    34	- `/usr/bin/telemetry.sh` — reads `TELEMETRY` from `/etc/sonic/config_db.json`
    35	  (file-based, so it starts before redis), selects TLS vs plaintext, and sets
    36	  `YANG_MODELS_PATH=/usr/local/yang-models/` so `sonic-*` gNMI paths resolve
    37	- `/etc/supervisor/conf.d/telemetry.conf` — `[program:telemetry]`
    38	
    39	## Verified (2026-08-31)
    40	
    41	- `supervisorctl status telemetry` → RUNNING; listening on `:8080`
    42	- `gnmic -a <node>:8080 --skip-verify -u admin -p admin capabilities` →
    43	  gNMI 0.7.0, OpenConfig acl/lldp/platform/system + `sonic-db`
    44	- `/usr/local/yang-models/sonic-srv6.yang` present (144 models)
    45	
    46	## Rebuild
    47	
    48	The build stages the telemetry binary out of a builder container that has the
    49	base image's libraries, then assembles this Dockerfile. The full driver script
    50	is `.wiggum/features/001-ainetops-sonic-evpn-fabric/build-gnmi/build5i.sh`;
    51	`docker build` here needs `telemetry`, `schema/` and `boost-libs/` staged
    52	alongside the Dockerfile first.
    53	
    54	After a rebuild, push and re-pin:
    55	
    56	    docker push localhost:5000/sonic-vs-gnmi:202605 && docker inspect --format '{{index .RepoDigests 0}}' localhost:5000/sonic-vs-gnmi:202605
    57	
    58	then update `versions.lock.yaml` (`sonic_images.sonic_vs` + the `sonic_yang.compatibility` row), `lab/topology.clab.yml`, and `lab/profiles/sonic-vs/profile.yaml` with the new digest.
