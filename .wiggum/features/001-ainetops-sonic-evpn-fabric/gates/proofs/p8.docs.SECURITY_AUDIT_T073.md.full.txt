     1	# Security Audit (T073, FR-015)
     2	
     3	This document records the Phase 8 security audit of RBAC verbs/scopes, Secret use, TLS validation, image privileges, Docker/KVM trust boundaries, Grafana plugin provenance, anonymous access/default credentials, and log/status redaction.
     4	
     5	Scope: all changes are within the open-source distribution and in-cluster resources. Evidence is grounded by the cited repository paths and proof slices under .wiggum/features/001-ainetops-sonic-evpn-fabric/gates/proofs/.
     6	
     7	## RBAC verbs and scopes
     8	
     9	- Base namespaces/RBAC/NetworkPolicies and controller RBAC are applied by scripts/lib/rbac.sh.
    10	- ServiceAccounts, Roles, and ClusterRoles are least-privilege and scoped to the ainetops-system namespace unless cluster-wide access is required by CRDs.
    11	- Evidence:
    12	  - config/rbac/service_account.yaml — service accounts for provider and SRv6 controller (proof: gates/proofs/config.rbac.service_account.yaml.slice.txt)
    13	  - config/rbac/role.yaml and role_binding.yaml — namespace-scoped permissions (proof: gates/proofs/config.rbac.role.yaml.slice.txt, gates/proofs/config.rbac.role_binding.yaml.slice.txt)
    14	  - config/rbac/cluster_role.yaml and cluster_role_binding.yaml — cluster-scoped reads for CRDs only as needed (proof: gates/proofs/config.rbac.cluster_role.yaml.slice.txt, gates/proofs/config.rbac.cluster_role_binding.yaml.slice.txt)
    15	  - deploy/rbac/srv6-crd-rbac.yaml — binds SRv6 CRD access to the controller SA (proof: gates/proofs/config.rbac.cluster_role.srv6.slice.txt)
    16	
    17	## Secret use
    18	
    19	- No static credentials are stored in Git. Lab credentials and TLS are generated in-cluster by one-shot Jobs:
    20	  - deploy/rbac/secret-generator-job.yaml — creates gnmi-lab-creds and gnmi-lab-tls (proof: gates/proofs/deploy.rbac.secret-generator-job.yaml.slice.txt)
    21	  - deploy/observability/grafana-secret-generator-job.yaml — creates grafana-admin (proof: gates/proofs/deploy.observability.grafana-secret-generator-job.yaml.slice.txt)
    22	- Consumers reference Secrets via secretKeyRef; no secret data is logged or embedded in manifests:
    23	  - deploy/gnmi/gnmic.yaml uses secretKeyRef for GNMIC_USERNAME/PASSWORD and mounts TLS keys; skip-verify: false and tls-ca/tls-cert/tls-key set (proof: gates/proofs/deploy.gnmi.gnmic.yaml.secretKeyRef.slice.txt, gates/proofs/deploy.gnmi.gnmic.yaml.tls.slice.txt)
    24	  - deploy/observability/grafana.yaml uses Secret grafana-admin for admin credentials (proof: gates/proofs/deploy.observability.grafana.yaml.flow-pin.slice.txt)
    25	
    26	## TLS validation
    27	
    28	- gNMIc configuration enforces TLS with JSON_IETF encoding and skip-verify: false; CA/cert/key mounted from Secret (deploy/gnmi/gnmic.yaml). (proof: gates/proofs/deploy.gnmi.gnmic.yaml.tls.slice.txt)
    29	
    30	## Image privileges and container hardening
    31	
    32	- Controllers and workloads run as non-root, drop all capabilities, and use read-only root filesystems where applicable:
    33	  - deploy/ainetops/manifests/provider.yaml sets runAsNonRoot, allowPrivilegeEscalation: false, readOnlyRootFilesystem: true, and capabilities: drop: ["ALL"] (proof: gates/proofs/deploy.ainetops.manifests.provider.yaml.security.slice.txt)
    34	  - cmd/sonic-provider/Dockerfile and cmd/srv6-controller/Dockerfile use minimal bases; security review proof slices captured (proof: gates/proofs/cmd.sonic-provider.Dockerfile.security.slice.txt, gates/proofs/cmd.srv6-controller.Dockerfile.security.slice.txt)
    35	
    36	## Docker/KVM trust boundaries
    37	
    38	- Preflight requires a Docker-compatible runtime and enforces /dev/kvm presence only when the sonic-vm profile is selected. This confines privileged virtualization to the conformance profile and prevents accidental use in the fast profile:
    39	  - scripts/lib/preflight.sh: preflight::runtime_privileges and preflight::kvm_check (proof: gates/proofs/scripts.lib.preflight.kvm_check.slice.txt)
    40	
    41	## Grafana plugin provenance and anonymous access
    42	
    43	- Grafana Flow plugin is pinned by immutable digest via GF_INSTALL_PLUGINS; anonymous access is disabled; admin credentials are pulled from a Secret generated at runtime:
    44	  - deploy/observability/grafana.yaml (proof: gates/proofs/deploy.observability.grafana.yaml.flow-pin.slice.txt)
    45	
    46	## Prometheus exposure and redaction posture
    47	
    48	- Prometheus is deployed for in-cluster scraping and does not enable the remote write receiver; no public endpoints are exposed by default in this lab configuration (proof: gates/proofs/deploy.observability.prometheus.yaml.slice.txt).
    49	- Controllers do not mount Secrets; credential handling is limited to gNMIc and Grafana via Kubernetes Secrets.
    50	
    51	## Logging/status redaction
    52	
    53	- Provider and SRv6 controller do not read or log secret contents. Status conditions use standard reason strings and omit secret values. No Secret volumes or envs are present in the controller manifests (see deploy/ainetops/manifests/provider.yaml; proof: gates/proofs/deploy.ainetops.manifests.provider.yaml.slice.txt).
    54	
    55	## Summary
    56	
    57	The audit confirms:
    58	- RBAC: minimal, scoped verbs; CRD reads bound to service accounts.
    59	- Secrets: generated at runtime; consumed via Secret refs; no secrets in Git.
    60	- TLS: gNMIc validates TLS (skip-verify: false) with CA/cert/key.
    61	- Hardening: non-root, no privilege escalation, RO rootfs, capabilities dropped.
    62	- Trust boundaries: Docker required; KVM required only for sonic-vm.
    63	- Provenance: Grafana plugin pinned by digest; anonymous disabled.
    64	- Exposure: Prometheus avoids remote write receiver; in-cluster only.
