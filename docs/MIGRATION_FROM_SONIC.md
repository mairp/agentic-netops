# Migration record: SONiC → Nokia SR Linux

This repository is the SR Linux edition of
[mairp/agentic-netops](https://github.com/mairp/agentic-netops). The intent
tier, the Kubernetes control plane, the CRDs, the operator console and the
observability stack are the same; the network operating system boundary was
replaced. The specification that drove the change lives in
`specs/001-agentic-netops-srlinux-evpn-fabric/`.

## Mechanism mapping

| Concern | SONiC (original) | SR Linux (this repository) |
|---|---|---|
| Image | `localhost:5000/sonic-vs-gnmi:202505-v1` (custom build with a layered gNMI server) | `ghcr.io/nokia/srlinux:26.7.2` (public, unmodified), containerlab kind `nokia_srlinux`, type `ixrd2l` |
| Node boot | containerlab `linux` kind + supervisord kick + bootstrap scripts (`init-sonic-bootstrap.sh`, `configure-fabric-bgp.sh`, self-repair loops for bgpd/zebra) | containerlab `startup-config` per node (`lab/profiles/srlinux/config/*.cfg`); no post-boot repair needed |
| Underlay | eBGP over /31 + /127, FRR `bgpd.conf` written by script | eBGP over the same addressing, declared in startup config; RFC 8212 policies explicit |
| Overlay | EVPN AF on the eBGP sessions, `advertise-all-vni`, FRR/zebra VNI adoption toggles | EVPN over iBGP (AS 65535) between system0 loopbacks, spines as route reflectors |
| Management/gNMI | sonic-telemetry on :8080, TLS material generated by a k8s Job and copied into nodes, PAM/sshd user | SR Linux gNMI server on :57400 with the containerlab TLS profile; generated user created over gNMI; the CA is published into `gnmi-lab-tls` |
| Write path | fabric-executor over the **docker socket**: GCU JSON patches, `redis-cli` CONFIG_DB rows, kernel `ip`/`bridge` commands, `vtysh` + `bgpd.conf` appends | fabric-executor over **gNMI Set** (JSON-IETF), one transactional commit per op, `tools system configuration save` after success |
| Verification | `redis-cli hget/exists`, `ip -d link`, `bridge vlan`, `vtysh show …` string matching | gNMI Get assertions (`gnmi-equals`, `gnmi-contains`, `gnmi-exists`, `gnmi-list-min`, `gnmi-absent`) on state paths |
| vlan | `VLAN|VlanN` row + Bridge port membership (PVID/tagged race) | `interface X subinterface N` (single-tagged) in mac-vrf `vlan-N` |
| mac-vrf | `VXLAN_TUNNEL_MAP` row, `vtep1-<vlan>` kernel device, FRR `vni` block under the leaf ASN | `tunnel-interface vxlan1 vxlan-interface <l2vni>` + mac-vrf with `bgp-evpn`/`bgp-vpn` (evi = vni, RT `target:…`) |
| ip-vrf | `VRF` row (GCU), derived L3VLAN SVI in the VRF, FRR per-VRF BGP with `redistribute connected` | ip-vrf network-instance, routed subinterface tagged with the derived L3VLAN, routed vxlan-interface; Type-5 originated natively |
| IRB | SVI addressed inside the VRF + L2 half | `irb0.<vlan>` with `anycast-gw` in both the mac-vrf and the ip-vrf |
| acl | `ACL_TABLE`/`ACL_RULE` rows bound to ports; ASIC_DB applied-side check | `acl acl-filter` entries bound to subinterfaces; entry statistics as applied-side check |
| Remote VTEP proof | `show evpn vni` `# Remote VTEPs` column | `vxlan-interface … bridge-table multicast-destinations` (learned from the peer's IMET) |
| Telemetry | gnmic on SONiC DB tables (`COUNTERS_DB`, `APPL_DB`, `CONFIG_DB`) | gnmic on `/interface[...]/statistics`, oper-state, BGP neighbor session-state, platform CPU/memory |
| Persistence | `/etc/sonic` named volume per node | node filesystem + `configuration save`; startup-config re-applied on `deploy --reconfigure` |
| SRv6 | qualified on the custom image (gate D1–D4) | not applicable on the SR Linux container: gate entries `not-applicable`, `SRv6Service` reports `CapabilityMissing` |
| Supply-chain policy | SR Linux artifacts forbidden | SONiC artifacts forbidden |

## What did not change

- The four constructs and their plain-language vocabulary; the mapper/allocator/deployer contracts; the two-confirmation flow.
- kuid pools (L3VNI 10000–14094: the ip-vrf attachment subinterface tag is still derived from the L3VNI, so the cap stays meaningful).
- `Network` schema, `Ready`/`Degraded` conditions, the 5-minute resync that repairs drift.
- The executor's HTTP API and its placement on the host bridge gateway; the intent tier still has no route to the devices.
- Namespaces, Secrets names, NetworkPolicies (the gNMI egress rule now targets port 57400).
