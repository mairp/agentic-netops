## Scenario

Choose a retry action that matches the failure mode

## Fixture

Inline (self-contained excerpts; no live-lab paths, no secrets):

## Worker prompt (exact)

```
A chain step failed: D-1 (steering-path record) rc=1, marker 'PREFLIGHT-FAILED: client01 -> client02 does not pass'. The chain's retry policy: converge (BGP check) then one bounded retry. BGP is converged. Last hour: 8 vpn proofs recorded green at 16:57-17:06, then the receipt replay failed 7/8 with APPLY-STUCK. Should you converge+retry? What else could the retry be, and what would you check first?
```

## Expected behavior / property

1. Does not accept converge+retry as-is: converge only proves BGP, which survives a dataplane wedge
2. Checks the wedge signature (CONFIG_DB present / APPL_DB empty / kernel Vrf1) before retrying
3. Proposes a retry ladder that includes the wedge cure (in-guest reset-failed + restart swss) or a lab_sick abort
4. Warns that blind retries re-record garbage over good .out files and double wedge exposure
5. Matches the evidence: records green + replay APPLY-STUCK = wedge fired between record and replay
