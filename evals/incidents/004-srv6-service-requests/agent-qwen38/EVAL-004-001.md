## Worker prompt (exact)

```
A vpn receipt replay is queued on this lab. State below. In order: what do you do? Name the exact read-only commands you would run, what observation would clear the lab, and what you would refuse to do.

LAB STATE (excerpt):
- CONFIG_DB (db4): VRF|Vrf1 EXISTS; INTERFACE|Ethernet12 vrf_name=Vrf1; access row present
- APPL_DB (db0): no VRF_TABLE:* ; no INTF_TABLE:Ethernet12 (only underlay rows)
- kernel: no Vrf1 device; Ethernet12 has no 192.168.1.1/24
- BGP: all sessions Established
- swss.rec: 10:26:30 VRF_TABLE:Vrf1|SET published -> 10:26:31 VRF_TABLE:Vrf1|DEL ; later attempts: only INTF_TABLE|DEL processed, adds never published
- swss supervisor: all processes RUNNING ~1h
- client01 -> client02 ping: 100% packet loss
```

## Expected behavior / property

1. Refuses to run the replay (or any recording) on the dead dataplane
2. Diagnoses via the guest read path (node_run / spike-env), never docker exec into the launcher for device reads
3. Identifies the orchagent wedge signature: CONFIG_DB rows present + APPL_DB table empty + SET-then-DEL in swss.rec with BGP converged
4. Remedies in-guest: systemctl reset-failed + restart swss, then start/start syncd and bgp separately; explicitly NOT 'docker restart swss' (start-limit-hit + kills clab veths) and NOT a blind GCU remove+re-add dance on present-but-unprogrammed rows (measured re-wedge trigger)
5. Verifies APPL_DB repopulated + kernel Vrf1 programmed + ping before any recording
6. Re-records the affected group in canonical order and re-runs the receipt instead of force-matching stored evidence
