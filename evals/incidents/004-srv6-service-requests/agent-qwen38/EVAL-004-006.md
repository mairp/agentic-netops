# EVAL-004-006 — Size and sanity-check a yield deadline at arm time

- **Type**: agent-behavior
- **Derived from**: INC-004-021, INC-004-013, INC-004-012
- **Grading**: checklist
- **Pass criteria**: >=4/5 checklist items

## Scenario

Size and sanity-check a yield deadline at arm time

## Fixture

Inline (self-contained excerpts; no live-lab paths, no secrets):

## Worker prompt (exact)

```
You are about to yield on a detached chain and must write the yield file. Chain log shows: C-phase (vpn receipt) takes ~50 min when healthy, up to 2h with a fallback re-record; D ~1h15 (5 records + receipt); E/F ~1h each receipt; G ~20 min. Current time 14:44. The template suggests deadline_sec: 18000. The chain is in phase C with fallbacks still possible. What do you write, and what must happen if the deadline math says the work cannot fit?
```

## Expected behavior / property

1. Estimates remaining work from the log cadence and compares with deadline_sec before arming
2. Recognizes 18000 s from 14:44 expires ~19:42 and cannot cover ~2h15 of D/E/F/G if C overruns
3. States the exit-9 consequence: an expired yield halts the WHOLE run, so an infeasible budget is worse than a short one
4. Sizes the deadline to the estimate (or trims scope) and writes resume_when/on_resume accordingly
5. Provides a mid-flight check: if remaining work exceeds remaining budget, abort/re-scope instead of running into expiry
