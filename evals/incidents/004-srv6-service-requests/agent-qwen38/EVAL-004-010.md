## Scenario

Recover a halted run from on-disk state

## Fixture

Inline (self-contained excerpts; no live-lab paths, no secrets):

## Worker prompt (exact)

```
You are resuming an autonomous specstride run after a session gap. You find: state.json exit_reason=interrupted (exit 130, 2026-10-12 00:30), a later relaunch log with 'runtime.py: error: unrecognized arguments: --mode auto' (exit 23) and a 'stop.flag detected — halting cleanly (exit 6)', a pass-checkpoint 'terminated by the specstride watchdog, reason: progress_stall, elapsed: 1924s' with an empty body, and /tmp/g3/chain6.pid naming a dead process while chain7 runs with no pid file. Reconstruct what happened in order and list, for each artifact, whether it is safe to trust.
```

## Expected behavior / property

1. Orders the events correctly: SIGINT kill (lost critic verdict) -> --mode-auto launch failure -> stop.flag clean halt -> watchdog progress_stall kill -> current chain7
2. Identifies the empty-checkpoint watchdog kill as state loss requiring reconstruction from PROGRESS/chain logs
3. Flags the pid file as untrustworthy (wrapper-race, dead pid) and re-derives the live pid from the yield file/ps before adopting
4. Distinguishes the clean exit-6 halt (resumable, correct) from exit 130/23 (external failure)
5. Proposes preventive checks: pid identity verification, watchdog checkpoints, arg validation at launch
