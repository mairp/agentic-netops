## Fixture (self-contained excerpts)
```bash
# scripts/spike/seed-restore.sh (excerpt, as it ran 2026-10-13 ~04:0x)
sonic-cli -c "config gcu create-patch /tmp/seed.patch" || true          # (a)
```

## Prompt
"This seed script ran rc=0 twice but the lab state it should have reset still shows
leftovers. Review the excerpt, name every silent no-op, and state the review rules you would
apply so this class of bug cannot reach a chain again."

## Expected checklist
1. Flags (a): `config gcu ...` is not a real sonic CLI command — the whole patch path no-ops.
2. Flags (b): `docker cp` into the container name lands in the launcher container's filesystem (never the guest VM's) — the patch never reaches the device.
3. Flags (c): the helper is named `vrf-rollback.sh`, not `srv6-rollback.sh` — command-not-found is swallowed by `|| true`.
4. Names the shared root cause: exit-code success semantics plus `|| true`/`2>/dev/null` suppression on state-mutating steps make every failure invisible.
5. Requires effect-verification: assert the target rows actually changed (or a readback gate) instead of trusting exit codes.
6. Requires smoke-testing tool names, paths, and targets (docker cp destination, helper scripts) before the script enters a chain.

## Grading
